# 系统监控模块使用说明

## 概述

本监控模块专门用于监控CentOS 7服务器的CPU和内存使用情况，特别适用于灾备系统采购参考。模块提供了多种监控方式，可以直接获取结果，无需手动计算。

## 功能特点

- ✅ **直接获取结果**：无需手动计算，直接显示CPU和内存使用率
- ✅ **多种监控方式**：支持top、vmstat、free等多种系统命令
- ✅ **持续监控**：可以持续监控一段时间，记录平均值、最大值、最小值
- ✅ **自动生成报告**：自动生成详细的监控报告和灾备系统采购建议
- ✅ **适用于CentOS 7**：针对CentOS 7系统优化

## 快速开始

### 1. 检查监控工具

首先检查系统是否已安装必要的监控工具：

```bash
# 加载模块
source ./lib/loader.sh

# 检查工具
check_monitor_tools
```

如果缺少工具，可以使用以下命令安装：

```bash
# CentOS 7
yum install -y bc sysstat
```

### 2. 显示当前系统资源（单次快照）

快速查看当前系统的CPU和内存使用情况：

source ./lib/loader.sh

### 3. 持续监控系统资源

持续监控一段时间，获取平均值、最大值、最小值：

```bash
source ./lib/loader.sh

# 监控10次，每次间隔5秒
monitor_system_resources 10 5

# 监控30次，每次间隔10秒（约5分钟）
monitor_system_resources 30 10
```

### 4. 使用vmstat进行详细监控

使用vmstat获取更详细的系统信息（包括I/O、中断、上下文切换等）：

```bash
source ./lib/loader.sh

# 监控10次，每次间隔5秒
monitor_with_vmstat 10 5
```

### 5. 生成灾备系统采购参考报告（推荐）

这是最实用的功能，会自动监控系统并生成包含采购建议的完整报告：

```bash
source ./lib/loader.sh

# 监控30次，每次间隔10秒（约5分钟），生成报告
generate_backup_report 30 10
```

报告将包含：
- 系统基本信息（CPU、内存规格）
- 系统资源使用情况统计（平均值、最大值、最小值）
- 灾备系统配置建议（CPU、内存配置建议）
- 其他采购建议

## 函数说明

### `show_system_resources`
显示当前系统资源使用情况（单次快照）

**用法：**
```bash
show_system_resources
```

### `monitor_system_resources [次数] [间隔秒数]`
持续监控系统资源

**参数：**
- `次数`：监控次数（默认：10）
- `间隔秒数`：每次监控的间隔时间，单位秒（默认：5）

**用法：**
```bash
monitor_system_resources 20 5  # 监控20次，每次间隔5秒
```

### `monitor_with_vmstat [次数] [间隔秒数]`
使用vmstat进行详细监控

**参数：**
- `次数`：监控次数（默认：10）
- `间隔秒数`：每次监控的间隔时间，单位秒（默认：5）

**用法：**
```bash
monitor_with_vmstat 10 5
```

### `generate_backup_report [次数] [间隔秒数]`
生成灾备系统采购参考报告

**参数：**
- `次数`：监控次数（默认：30）
- `间隔秒数`：每次监控的间隔时间，单位秒（默认：10）

**用法：**
```bash
generate_backup_report 30 10  # 监控30次，每次间隔10秒（约5分钟）
```

### `check_monitor_tools`
检查监控工具是否已安装

**用法：**
```bash
check_monitor_tools
```

## 报告文件位置

所有生成的报告文件都保存在日志目录中：
```
~/.LOG/ProjectManage.sh_LOG/
```

报告文件命名格式：
- 系统资源监控报告：`system_monitor_YYYYMMDD_HHMMSS.txt`
- vmstat监控报告：`vmstat_monitor_YYYYMMDD_HHMMSS.txt`
- 灾备系统采购报告：`backup_system_report_YYYYMMDD_HHMMSS.txt`

## 注意事项

1. **监控时长建议**：
   - 快速查看：使用 `show_system_resources`（单次快照）
   - 短期监控：监控10-20次，间隔5秒（约1-2分钟）
   - 中期监控：监控30次，间隔10秒（约5分钟）
   - 长期监控：监控60次，间隔10秒（约10分钟）

2. **空闲时监控**：
   - 为了获得准确的空闲时资源使用情况，建议在系统相对空闲时进行监控
   - 避免在系统执行大量任务时监控

3. **业务高峰期监控**：
   - 除了空闲时监控，也建议在业务高峰期进行监控
   - 综合两个时间段的数据，可以更准确地评估灾备系统需求

4. **工具依赖**：
   - 基本功能需要 `bc` 命令（通常已预装）
   - vmstat功能需要 `sysstat` 包
   - 如果缺少工具，脚本会提示安装命令

## 常见问题

### Q: 为什么CPU使用率显示不准确？
A: 脚本会尝试多种方法获取CPU使用率（top、vmstat、/proc/stat）。如果都不准确，可能是系统负载变化太快。建议使用 `monitor_with_vmstat` 获取更准确的数据。

### Q: 如何查看历史监控报告？
A: 所有报告都保存在 `~/.LOG/ProjectManage.sh_LOG/` 目录中，可以使用 `ls -lt` 查看最新的报告。

### Q: 监控会影响系统性能吗？
A: 监控本身对系统性能影响很小。但如果监控间隔太短（如1秒），可能会产生一些开销。建议间隔至少5秒。

### Q: 可以在多台服务器上使用吗？
A: 可以。在每台服务器上分别运行监控脚本，然后对比各服务器的报告即可。

## 技术实现

监控模块使用以下系统命令和文件：
- `top`：获取CPU使用率
- `vmstat`：获取详细的系统统计信息
- `free`：获取内存使用情况
- `/proc/stat`：CPU统计信息
- `/proc/meminfo`：内存统计信息
- `/proc/cpuinfo`：CPU硬件信息
